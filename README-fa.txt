# Study OS v94 — نامزد انتشار

این بسته نسخهٔ آمادهٔ بازبینی برای انتشار روی آدرس اصلی Study OS است. **هنوز منتشر نشده و هیچ تغییری در GitHub Pages یا Supabase اعمال نمی‌کند.** پیش از ادغام با `main` باید راهنمای انتشار را بخوانید و بخش‌های مربوط به Supabase/Edge Functions را با احتیاط و در زمان مناسب انجام دهید.

## مبنای نسخه و سازگاری

- مبنای رابط و قابلیت‌های پایدار، نسخهٔ سالم v91 است؛ افزونه‌های v93.2.1 روی همان ساختار اضافه شده‌اند.
- شناسه‌های محلی تنظیمات و نشست ابری به کلیدهای قبلی v79 برگشته‌اند تا حساب ورود و تنظیمات پروژهٔ فعلی از دست نروند.
- نشانی پروژه و کلید عمومی publishable موجود در نسخهٔ v91 حفظ شده‌اند. این کلید عمومی است؛ هیچ `service_role`، secret key یا کلید OpenAI در کد مرورگر قرار نگرفته است.
- فهرست همگام‌سازی ابری اکنون فقط شامل دو مخزن آموزشی `pasokhBargDigitalV2` و `pasokhBargStudyOS_v2` است. تم، RGB، چیدمان دستگاه، حالت پنل، موسیقی و تنظیمات نمایشی محلی‌اند. چند تنظیم وابسته به دستگاه که داخل شیء مطالعه ذخیره می‌شوند نیز قبل از ارسال حذف و هنگام دریافت از مقدار همان دستگاه حفظ می‌شوند.
- در نخستین همگام‌سازی موفق، کلیدهای قدیمیِ تنظیمات نمایشی که ممکن است در Snapshot ابری قبلی وجود داشته باشند از payload ابری حذف می‌شوند؛ مقدار محلی همان دستگاه حفظ می‌شود. از فایل پشتیبان JSON خود نگهداری کنید.
- مدل Sync همچنان Snapshot-based است. همگام‌سازی مستقل event/record برای تک‌تک سؤال‌ها در این نسخه پیاده نشده است.

## تغییرات اصلی

1. ثبت آزمون‌های بیرون از سامانه با تعداد کل/درست/غلط/نزده، درصد محاسباتی و درصد رسمی جدا، تراز و رتبهٔ رسمی، درس/مبحث/منبع و ارسال سؤال‌های مهم به مرور.
2. اصلاح به‌روزرسانی پاسخ‌برگ برای تغییر کارت سؤال مربوط، بدون بازسازی کل فهرست سؤال‌ها در هر پاسخ.
3. حفظ اعداد فارسی تایمر آزمون و زمان‌سنج مطالعه؛ تابع قالب‌بندی با نسخهٔ پایدار v91 مقایسه شده است.
4. انتخاب خالی درس، منبع و فصل برای آزمون جدید؛ بازکردن آزمون قبلی مسیر خودش را بازمی‌گرداند.
5. زمان‌سنج با هشدارهای مختلف و بازهٔ ۱۰ ثانیه‌ای تصمیم؛ در این بازه زمان مطالعه شمرده نمی‌شود و در صورت بی‌پاسخ‌ماندن، زمان‌سنج ادامه می‌یابد.
6. برنامه‌ریزی منعطف با ساعت اختیاری و ترتیب/اولویت فعالیت‌ها.
7. گزارش روزانه با جزئیات جلسه‌ها، برنامه‌ها، کارها و آزمون‌های هر درس؛ گزارش چندروزهٔ تجمیعی و انتخاب جداگانهٔ هفت گزارش روزانه.
8. تحلیل نتیجه با تفکیک درصد رسمی و محاسباتی، نسبت غلط به درست، و هدف تمرینی مبتنی بر سه آزمون مشابه اخیر. هدف ۵ تا ۱۰ واحد درصد بالاتر، پیش‌بینی علمی نیست؛ تراز از روی درصد حدس زده نمی‌شود.
9. تقویم شمسی با رویدادهای استخراج‌شده از برنامه‌های کانون، ماز و آرمان. تاریخ‌ها از فایل‌های ارسالی گرفته شده‌اند؛ شماره‌صفحه‌ها یا بودجه‌بندی‌های ناخوانا حدس زده نشده‌اند. برای آرمان فقط بودجهٔ زیست با اتکا به جدول خوانا وارد شده است.
10. موسیقی فقط از طریق YouTube باقی مانده است. گزینهٔ «موسیقی» در انتهای نوار کناری قرار دارد تا روی محتوای صفحه شناور نباشد. پخش مستقیم ممکن است بر اساس محدودیت YouTube/شبکه پیام ورود یا تأیید نشان دهد؛ برنامه هیچ محدودیت شبکه‌ای را دور نمی‌زند. بازکردن در YouTube همچنان موجود است. سیستم موسیقی آفلاین یا مستقل اضافه نشده است.
11. رابط هوش مصنوعی و توابع Edge Function مستقل؛ کلید API فقط سمت سرور قرار می‌گیرد. AI تا زمانی که مهاجرت و تابع منتشر نشده، مدل معتبر در `OPENAI_MODEL` تنظیم نشده، و سرپرست قانونی موافقت نکرده و شناسهٔ حساب در allowlist سمت سرور نباشد، پاسخ‌گو نخواهد بود. هزینهٔ API جداست و فعال‌سازی باید با نظارت سرپرست انجام شود.
12. مدیریت حساب با نقش مدیر اصلی/مدیر کمکی، دعوت ایمیلی، مجوز اشتراک داده با رضایت مالک و ثبت ممیزی. فرم عمومی ساخت حساب در رابط حذف شده و دعوت با ایمیل انجام می‌شود؛ callback دعوتِ Supabase و تنظیم گذرواژه پشتیبانی شده‌اند. تنظیم «غیرفعال‌کردن ثبت‌نام عمومی» در Supabase Dashboard هنوز باید دستی و فقط پس از آزمایش موفق دعوت انجام شود.
13. Service Worker و حافظهٔ موقت با شناسهٔ v94 به‌روزرسانی شده‌اند تا فایل‌های جدید بارگذاری شوند.

## نکات ضروری پیش از انتشار

- `main` را فقط از طریق Pull Request به‌روزرسانی کنید و نسخهٔ قبلی را نگه دارید.
- فایل ZIP و فایل پشتیبان JSON را به‌عنوان دو نسخهٔ مستقل نگه دارید؛ فایل پشتیبان را در GitHub بارگذاری نکنید.
- SQL migration به‌صورت خودکار اجرا نمی‌شود. ابتدا آن را بازبینی کنید؛ سپس در صورت تأیید، فقط یک بار در پروژهٔ Supabase موردنظر اجرا کنید.
- برای Edge Functions، Supabase محیطی مانند `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEYS`, `SUPABASE_SECRET_KEYS` را در runtime فراهم می‌کند. Secrets اختصاصی را فقط در Dashboard > Edge Functions > Secrets وارد کنید.
- `APP_ORIGIN` باید فقط scheme + host (بدون مسیر `/study-os`) باشد: `https://mohammadkariman040-crypto.github.io`. خود تابع دعوت، مسیر `/study-os/` را به Redirect اضافه می‌کند.
- `STUDY_OS_ADMIN_USER_ID` باید UUID واقعی حساب مدیر اصلی در Auth باشد. کلید یا رمز حساب را در چت یا مخزن عمومی ننویسید.
- `OPENAI_API_KEY`, `OPENAI_MODEL` و `STUDY_OS_AI_GUARDIAN_APPROVED_USER_IDS` فقط پس از بررسی حریم خصوصی و موافقت سرپرست قانونی تنظیم شوند. `OPENAI_MODEL` باید نام مدلی باشد که واقعاً برای پروژهٔ API در دسترس است؛ هیچ مدل پیش‌فرضی حدس زده نشده است.
- پیش از خاموش‌کردن ثبت‌نام عمومی در Supabase Auth، دعوت ایمیلی را با یک حساب آزمایشی بررسی کنید. اگر دعوت کار نکرد، تنظیم را تغییر ندهید تا دسترسی حساب موجود از بین نرود.

## بازگشت

اگر بعد از انتشار مشکل دیده شد، نسخهٔ پیشین را از GitHub برگردانید و مطمئن شوید Service Worker نسخهٔ قبل نیز دوباره منتشر شده است. هیچ‌گاه Local Storage یا دادهٔ `study_os_sync` را برای رفع مشکل حذف نکنید.
